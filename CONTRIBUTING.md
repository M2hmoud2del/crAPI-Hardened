# Contributing to crAPI-Hardened

First off, thank you for considering contributing to crAPI-Hardened! It's people like you that make this security project a great learning resource for the community.

## How to Contribute

### 1. Reporting Vulnerabilities
If you have found a security vulnerability, please do **NOT** submit a public pull request or issue without reading our [Security Policy](SECURITY.md). Please use the **Vulnerability Report** issue template to ensure your report is handled responsibly.

### 2. Submitting Pull Requests
We welcome pull requests for documentation improvements, repository organization, and non-security bug fixes.
* **Fork the repository** and create your branch from `main`.
* If you've added code or documentation that should be tested, add tests.
* Ensure your PR description clearly describes the problem and solution.
* Use the provided **Pull Request Template**.
* **Important:** Do NOT submit pull requests that fix vulnerabilities or alter the core logic of the application unless specifically requested in an open issue. The goal of this fork is structured hardening and education.

### 3. Improving Documentation
Documentation is crucial. Whether it's fixing a typo, expanding a guide in `/docs/`, or writing up a new vulnerability fix, your help is appreciated. Use the **Documentation Improvement** issue template or submit a PR directly for minor typos.

### 4. Community Participation
Join the conversation in **GitHub Discussions**!
* Share ideas for new hardening phases.
* Ask questions about specific API security concepts.
* Help other researchers troubleshoot their setups.

## Code of Conduct
Please be respectful and professional in all interactions. We are building an inclusive environment for researchers of all skill levels.

Thank you for contributing!
